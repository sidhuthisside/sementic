# Contributing to Semantic Intel

We love your input! We want to make contributing to Semantic Intel as easy and transparent as possible, whether it's:

- Reporting a bug
- Discussing the current state of the code
- Submitting a fix
- Proposing new features
- Becoming a maintainer

## Our Development Process

We use GitHub to track issues and pull requests.

1.  **Fork** the repo and create your branch from `main`.
2.  If you've added code that should be tested, **add tests**.
3.  If you've changed APIs, **update the documentation**.
4.  Ensure the test suite passes.
5.  Make sure your code lints.
6.  Issue that **pull request**!

## Pull Request Guidelines

- Give your PR a descriptive title.
- Link to relevant issues if they exist.
- Provide a summary of your changes and why you made them.
- Include screenshots or recordings if your changes affect the UI.

## Coding Style

- Use TypeScript for all new code.
- Follow the existing project structure.
- Ensure your code is well-commented, especially for complex logic in `lib/analyzer`.
- Use Tailwind CSS for styling.

## Reporting Issues

Use the GitHub Issue Tracker to report bugs or request features. Please provide as much context as possible, including steps to reproduce the issue.
